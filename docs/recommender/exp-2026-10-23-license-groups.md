# 면허 제한 그룹을 대안(OR)으로 (2026-10-23) · **채택** (10/1 시험 통과)

[exp-2026-10-23-eval-realign.md](exp-2026-10-23-eval-realign.md) 에서 자격 단계 정답 손실의 99% 가 면허였다. 회사가 실제로 낙찰한 공고인데 "면허 미충족"으로 빠진 것이다.

## 원인

`check_qualifications` 가 면허 제한 그룹(`bid_license_limits.lmt_grp_no`)을 **모두 충족해야** 통과시켰다. 데이터로는 그룹이 서로 **대안**이다.

9/1 면허 탈락 120건을 회사 면허 원문과 대조(`t` 시점 필터 탓은 2건뿐, 118건은 현재 면허로도 불일치). 대표 예:

- 정기안전점검 용역 — 그룹1 안전진단전문기관(건축분야) / 그룹2 안전진단전문기관(종합분야) / 그룹3 안전점검전문기관(건축 분야). 안전점검전문기관만 가진 회사가 낙찰.
- 유학생 지원 프로그램 용역 — 그룹1 학술.연구용역 / 그룹2 기타자유업(행사대행업). 행사대행업만 가진 회사가 낙찰.
- 소방공사 — 그룹1 전문소방시설공사업 / 그룹2 일반소방시설공사업. 전문소방만 가진 회사가 낙찰.

검증: **실제 입찰 참가자**(낙찰·유찰 모두 — 자격이 있었던 게 확실한 회사) 7~9월 공고 10,086쌍에서 판정 규칙별 통과율.

| 규칙 | 전체 | 그룹 2개+ 공고 (2,955쌍) |
|---|---|---|
| 그룹 AND, 그룹 안 하나 (이전 코드) | 81.5% | **41.9%** |
| 그룹 OR, 그룹 안 하나 (채택) | **98.3%** | **98.9%** |
| 그룹 OR, 그룹 안 전부 | 96.4% | 94.2% |

그룹 안에 서로 다른 면허가 둘 이상이고 그중 하나를 가진 참가자 2,255명 중 829명이 일부만 가졌다 → 그룹 안도 하나면 된다.
남은 1.7% 는 면허명 개편(종합여행업 ↔ 국내외여행업 등)·공동수급 등으로 보인다 — 확인하지 않았고 이번엔 손대지 않았다.

## 수정

`app/recommender/qualifications.py` — 어느 한 그룹의 면허 하나만 있으면 통과. 자체 점검에 그룹 OR·그룹 안 하나 케이스 추가.
운영(v2 `rank_v2`)과 `/qualifications/check` 라벨, 하네스가 이 함수 하나를 쓴다. v1 `recommend.py::_check_license_pass` 에도 같은 AND 가 있으나 기본 경로가 아니라 건드리지 않았다.

## 운영 영향

운영 `rank_v2` 도 같은 함수로 하드 제외하므로, 그룹이 2개 이상인 공고는 지금까지 실제로 낼 수 있는 회사에게도 절반 넘게 숨겨졌다. 배포하면 결과 페이지 "참가 자격 통과" 수가 늘어난다.
회사 SEO 페이지 추천 캐시(`company_recommendations`)는 이전 판정으로 만들어진 것이라 다음 재계산까지 옛 결과가 남는다.
