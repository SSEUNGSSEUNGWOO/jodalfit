# 2026-10-28 코드 점검 후 수정

- 회사 SSR 추천 캐시는 최대 1시간만 재사용한다. 조회 시 회사의 비공개·제재 여부와 공고의 취소 차수·입찰참가자격 등록 마감을 확인한다. 공고 제목·마감·허용업종·참가 지역 변경이나 조회 실패도 캐시 미스로 처리한다. 기존 캐시는 payload 버전으로 무효화하며 스키마 변경은 없다.
- 스트리밍 API는 `with_explanation=false`면 `explain_top` 값과 관계없이 LLM을 호출하지 않는다. 검색 로그에도 실제 요청 옵션을 기록한다.
- 표시용 `score`는 자격 확인불가 감점이 반영된 `score_raw`로 계산한다. 후보 검색·자격 판정·정렬·MMR·가중치는 변경하지 않았으므로 과거 시점 채점표 재평가 대상인 랭킹 변경은 없다.
- hourly-sync는 회사 등록·공고 수집·상세 필드·임베딩을 계속 실행한 뒤 각 단계의 원래 `outcome`을 확인해 실패 또는 미실행이면 워크플로를 실패시킨다. IndexNow 실패는 계속 비차단이다. daily-sync의 DB 기반 수집 건강 점검은 그대로 유지한다.

검증: `cd backend; uv run --no-sync python -m unittest discover -s tests -v`.
테스트는 DB·LLM·외부 API 호출 없이 캐시 상태 변경·만료·재사용, 설명 생략·생성, 표시 감점 반영을 검사한다.
