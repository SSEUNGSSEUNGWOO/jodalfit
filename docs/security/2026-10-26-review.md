# 보안 점검 2026-10-26 — 가입 도입 뒤 첫 점검

범위: 프론트(Next.js 16, Vercel) · 백엔드(FastAPI, Railway) · Supabase(Auth·RLS·뷰·RPC) · 의존성.
방법: 코드 읽기(에이전트 2갈래) + 운영에 직접 침(공개 anon 키로 REST/RPC/Auth, 위조 헤더, 응답 헤더, `npm audit`·`pip-audit`).
운영 변경은 전부 되돌릴 수 있는 것만 했다(revoke → grant, 헤더·옵션 → 코드 revert).

## 확인했지만 문제 없음

- **RLS**: public 표 26개 전부 RLS on. 정책은 `saved_companies`·`reviewed_notices`(본인 행)·`user_consents`(본인 읽기·marketing_opt_in 갱신)만. 나머지는 정책 0 = service_role 전용. anon 키로 전부 0건(위 뷰만 예외였다). materialized view 는 grant 자체가 없다.
- **RPC**: anon 에 노출된 함수 중 `security definer` 는 `handle_new_user_consent`(트리거)·`rls_auto_enable`(이벤트 트리거)뿐. `find_companies`·`match_*`·`marketing_daily_stats`·`next_bid_notices_for_*` 는 invoker 권한이라 anon 으로 부르면 빈 결과(확인).
- **요청 제한 키**: Railway 는 `X-Forwarded-For` 를 진짜 클라이언트 IP 로 **덮어쓴다**(위조값 3종으로 보내도 ip_hash 동일). 첫 값을 키로 쓰는 `rate_limit.py` 는 그대로 둔다. (에이전트가 "첫 값이 위조 가능" 이라 보고했으나 실측으로 반증.)
- **Auth**: 이메일+비밀번호만, 자동 확인 없음(`mailer_autoconfirm=false`), 외부 공급자 없음. 틀린 비밀번호 15회 연속은 전부 400(계정 잠금 없음·429 없음 — Supabase 기본 토큰 한도는 IP당 30회/5분이라 그 안).
- **열린 리다이렉트**: `safe-next.ts` 가 `//`·`/\`·`://`·제어문자·auth 경로를 거른다. `from`(피드백)·`company`(추천)는 정규식 검사.
- **service_role**: `lib/supabase-server.ts` 만 쓰고 그 파일과 admin·auth·saved·supabase/server 전부 `"server-only"`. git 이력에 `.env*`·JWT·`sk-`·DSN 없음.
- **PostgREST 필터 주입**: `.or()` 에 사용자 입력 없음. `find_company` 의 ilike 는 `_name_core` 가 영숫자만 남긴다.
- **운영 `/docs`·`/openapi.json`** 404. 타 origin preflight 400. 예외 핸들러는 일반 문구만.
- **JSON-LD**: `serializeJsonLd` 가 `<` 를 `<` 로. `dangerouslySetInnerHTML` 은 그 둘뿐.
- **IP 해시**: `sha256(ip+salt)[:16]`. salt 는 운영 env 에 있음. HMAC 으로 바꾸면 기존 해시와 끊긴다 — 보관 1년이라 필요 시 교체 시점을 정해서.

## 남은 것 (결정 필요)

1. **HIBP 켜기** — 위 #3, 대시보드 한 번.
2. **가입 캡차**(Supabase Auth → Bot and Abuse Protection, Turnstile 무료). 지금은 가입 폼이 메일 발송을 일으키므로 스팸 가입이 Resend 한도를 태울 수 있다. 가입자 2명인 지금은 급하지 않다.
3. **전체 CSP** — `script-src` nonce. PostHog·Sentry·Next 인라인 스크립트 정리가 먼저.
4. **`lib/subscribe.ts` 웨이팅리스트 서버 액션** — 검증 약함(`includes("@")`, bizrno 미검사)이고 더블 옵트인 없음. 다만 이를 쓰는 `EmailCaptureForm`·`SubscribeBand`(`board/`)는 리뉴얼 뒤 어느 페이지에서도 import 되지 않는 죽은 코드라 노출 경로가 없다. 지우거나, 되살릴 때 고친다.
5. `/recommendations/stream` 의 LLM 호출 상한 — `explain_top≤10`·v1 알고리즘·키워드 모드를 조합하면 요청당 최대 20회. IP 당 40/분 제한 안이라 비용 폭주는 아니지만, 외부 호출엔 `explain_top≤5`·v2 고정이 맞다. 보드 화면이 실제로 보내는 값을 확인하고 조이기.
6. `/feedback` 알림 메일 — IP 당 30/일이라 하루 수천 통은 안 되지만, 전역 일일 상한(예: 100통)과 Resend 대시보드 한도 알림은 걸어 두는 게 좋다.
7. 글로벌 300/분 캡이 UA·referer 검사보다 먼저라, 403 받을 요청도 캡을 소모한다 — 순서 바꾸기(한 줄).
