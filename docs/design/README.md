# 디자인 리뉴얼 — 2026-10-13 결정 사항

Phase 3(로드맵 `docs/roadmap-2026-10.md`) 작업의 기준점. 프로토타입은 `prototypes/`의 HTML을 브라우저로 열면 그대로 보인다(외부 의존 없음, Pretendard는 CDN).
생성 스크립트는 `scripts/`에 있고 `backend/.env`의 `DATABASE_URL`로 실제 공고·회사 데이터를 읽어 다시 만들 수 있다
(`python scripts/gen_main_toc.py out.html`, UMAP 지도는 umap-learn·scikit-learn 필요).

## 방향
- **제품 화면이 곧 랜딩.** 그래픽 비유(바코드·별자리·궤도 등)는 전부 검토 후 폐기. 실제 결과 표·실제 공고명·실제 숫자로만 만든다.
- 연출은 **Attio 문법**: 소프트 워시 배경 + 점 격자, 둥근 흰 카드(14~16px), 가는 회색 연결선, 파스텔 아이콘 타일·칩, 알약형 내비.
- 색: 먹 4단계 + 인주 `#e8431b` 하나. 마감 칩만 파스텔(D-1 인주, 7일 내 노랑). 다크 모드 없음.
- 서체 Pretendard, 표 숫자 tabular, 글자 크기 4단계(11 / 12.5 / 13.5 / 제목).

## 머리 장면 = 로딩 가림막 (2026-10-15 결정)
메인 애니메이션(`prototypes/flow.html`, 선 9,285개가 관문 셋을 지나 12개로)은 **연출이 아니라 계산 대기 시간을 메우는 것**이다. 그러므로:
- **계산이 안 걸리면 안 보여준다.** 캐시 히트·재방문이면 결과가 즉시 뜬다. 지금 시안의 "재방문(짧게) 1.1초"도 0 이어야 한다.
- **고정 타임라인이 아니라 실제 진행에 묶는다.** 깔때기 네 칸이 파이프라인 네 단계와 그대로 대응한다 — 후보 검색 끝 → 831, 자격 거르기 끝 → 385, 점수·MMR 끝 → 12. 가짜 진행률을 만들지 않는다.
- 계산이 먼저 끝나면 현재 단계만 마무리하고 결과로 넘어간다. 계산이 길어지면 마지막 단계에서 기다린다.
- 그래서 **건너뛰기(아무 데나 클릭·Esc)는 보조 수단**이다. 필요한 이유 자체를 줄이는 게 먼저다.
- 참고 수치: 회사 모드 1.7초 / 키워드 모드 0.5초, p95 5.3초(2026-10-14). LLM 설명이 대부분을 차지한다.

**알려진 결함(미수정, 구현 때 같이):** 선 덩어리에 의미 없는 가로 검은 얼룩이 보인다. 코호트별 불투명도 차이(5.5% vs 30·34%)가 섞여 있고, 통과 선이 관문 직전 20px 에서 급히 휘며 겹치고, 선 간격 0.039px 가 픽셀 격자와 맞물려서다. 고치려면 코호트 불투명도를 통일하고 수렴 구간을 늘린다.

## 표현·요소 결정 (2026-10-15)
- 라벨: **참가 자격** / **추천 근거** ("낼 수 있나"·"왜 남았나"는 내부 사고방식이 드러나 폐기). 버튼은 **검토** 하나(옛 "검토 인장"), 상태는 "검토함".
- **"안 맞아요" 버튼은 지금 만들지 않는다** — 사용자 신호를 모으려던 것인데 로그인 사용자가 아직 없다. 불만이 관측되면 그때.
- **적합 점수 숫자(58 등)는 노출하지 않는다** — 58과 52의 차이를 설명할 수 없고, "낙찰 예측이 아니라 검토할 공고 디스커버리"라는 톤과 어긋난다. 대신 **숫자 없는 가는 막대**만. 정렬이 이미 적합 순이라 순서가 점수를 말한다. 펼침의 "적합 58/100"도 제거.
- **근거는 반드시 남긴다**(숫자와 다른 문제): 행마다 가장 강한 신호 칩 1개, 펼치면 근거 문장 전부. 나라장터와 다른 유일한 지점.
- 숫자 표기 사실 관계: 9,285 는 "오늘 올라온" 이 아니라 **"지금 입찰 가능한"** 공고(마감 90일 이내).
- **MZ풍(큰 둥근 모서리·파스텔 블롭·이모지·말 거는 말투) 금지.** 사용자는 하루 수십 건을 훑는 입찰 담당자이고, 유행 디자인은 1~2년이면 늙는다. "요즘 것 같다"는 느낌은 장식이 아니라 **움직임·전환·여백의 밀도**에서 — Linear·Attio 가 그 방향.
- 발주기관 로고·유형 표식: **안 한다**. 기관이 9,923개라 상위 100개로도 공고의 20%뿐이고(2026-10-15 실측), 유형 구분은 입찰 결정에 거의 영향이 없다.

## 공고 상세 시안 (2026-10-15, `scripts/gen_notice.py`)
세 안 모두 같은 실제 공고 3건 × 비로그인/회사 확인됨을 담고, 아래 스위치로 전환한다.
- `prototypes/notice-verdict.html` — 제목 다음이 참가 자격. 자격 → 과업 → 조건 → 단계 → 기관.
- `prototypes/notice-brief.html` — 좁은 단. 문서 요약을 가장 큰 글로 먼저.
- `prototypes/notice-rail.html` — 오른쪽 고정 레일에 마감·자격·수치, 본문은 과업부터.

**승우님 선택: `notice-rail.html`** (2026-10-15). 선택 후 고친 것 — 레일 시안에만 적용했고 나머지 두 안은 비교용으로 그대로 둔다.
- **영문 enum 노출 제거.** `requirements[].kind`(region/license/certification/performance/company_size/other)를 한글 라벨로(`KIND_KO`). DB 값을 입찰 담당자에게 그대로 보여 주지 않는다.
- **레일과 본문의 역할 분리.** 레일은 **판정 한 줄 + 두 줄 요약**만(늘 화면에 있으므로 짧아야 한다). 허용업종 전체 목록·판정 근거·기준·문서 조건 목록은 본문 `참가 조건`이 갖는다. 비로그인 게이트도 레일에만 둔다.
- **금액 표기 하나로.** 페이지 전체가 `1,202,000,000원`(억/만 줄임 폐기). 추정가·배정예산·기초금액은 **서로 다른 수**이므로 합치지 않는다 — 표기만 통일했다(공고 C 는 셋이 우연히 같다).
- **진행 단계 = 빈 상태가 기본 모양.** 낙찰·계약 기록이 없으면 `진행 단계`와 `개찰·계약` 두 빈 섹션 대신 접힌 한 줄("지금은 입찰 공고 단계 — 마감까지 N일" + 앞으로 들어올 것 + 연결 기록 유무), `6단계 전체`로 펼친다(`<details>`, JS 없음). 기록이 있으면 종전대로 6단계 + 개찰표.
- **자격 두 층을 시각적으로도 분리.** 판정하는 것은 공고 필드 제한(허용업종·지역) **둘뿐**. ✓ 는 먹, 어긋난 것만 인주(초록 ✓ 폐기 — 색은 먹 + 인주 하나). 레일은 느낌표를 줄 세우지 않고 왼쪽 괘선 2px 로만 표시한다.
- **"N건 중 등록업종으로 확인되는 것 M건" 폐기.** `text.split()[0] in m` 부분일치라 양방향으로 틀릴 수 있었다. 시스템이 아는 것은 "문서에 이런 요구가 적혀 있다"까지 — `면허 4건 · 증명 2건 — 서류로 증빙합니다. 판정하지 않습니다.` 로 바꿨다.
- **정정 이력을 맨 앞으로.** 정정이 있는 공고에서만 본문 첫 섹션. 마감이 움직였으면 레일 D-day 바로 아래에 `마감이 10.19 → 10.16 로 당겨졌습니다` 를 인주로 띄운다. 나라장터에서는 차수를 하나씩 열어 눈으로 비교해야 보이는 것이고, 당겨진 마감은 돈이다.
- 모바일(≤980px): 레일을 `order:-1` 로 본문 위에 올린다. **고정은 포기** — 390px 하단 고정 바는 아직 안 만들었다.

데이터에서 확인한 것(시안이 아니라 사실):
- **인사이트와 라이프사이클은 거의 겹치지 않는다.** 필수 조건이 많은 공고는 아직 진행 중이라 낙찰·계약이 없고, 사전규격→계약까지 이어진 공고는 첨부문서 인사이트가 없다. 사전규격 중 공고번호가 이어진 행은 187건뿐. "6단계가 다 찬 화면"은 사실상 없다 — 빈 칸이 기본값이다.
- `schedule` 에는 모델이 문자열 `"null"` 을 넣어 두는 칸이 있다. 없는 것으로 처리해야 한다.
- 자격은 두 층으로 나눈다: 공고 필드의 제한(허용업종·지역)은 판정할 수 있고, 문서에서 읽은 면허·증명은 서류로만 증빙돼 자동 판정하지 않는다.

## 검색 입구 시안 (2026-10-16, `scripts/gen_entry.py`)
회사명·사업자번호·하는 일을 **한 칸**에 받아 결과 페이지(flow.html 머리)로 넘기는 화면. 메인 랜딩 자체는 범위 밖.
- 전제(실측): 최근 7일 사용자 검색 395건 중 **205건(52%)이 회사로 풀리지 않았다** — 163건은 처음부터 키워드 모드, 42건은 회사 모드에서 "회사를 찾을 수 없습니다". 친 문자열은 "감리"·"주차"·"MIS"·"ADATA" 같은 낱말·브랜드. 그래서 키워드 길은 실패 뒤의 위로가 아니라 **회사 길과 같은 무게**로, 첫 글자부터 목록 안에 "이 말로 공고 찾기" 행이 같이 선다. 회사가 30곳 넘게 걸리는 낱말("감리" 61곳)은 키워드 행이 앞선다.
- 동명 회사: `find_company` 가 계약 건수로 하나를 고르던 것을 사용자가 고르게 한다. 구분자는 **지역(시·도 시·군) · 대표업종 1개 · 수주 건수 · 가린 사업자번호(137-XX-X4567)**. 묶음은 실제 행(대신네트웍스 17곳 — 전부 정보통신공사업이라 지역·수주로만 갈린다 / 한결 / 다온엔지니어링 / 신성건설).

## 입구 = 흐름의 첫 장면 (2026-10-16, `scripts/gen_entry_flow.py` → `prototypes/entry-flow.html`)
위 세 입구 안이 "검색창에 표 붙인 것"으로 판정돼, 입구를 별도 화면이 아니라 **flow.html 머리 장면의 첫 컷**으로 만든 안.
- 상태 0: 지금 입찰 가능한 공고 전부(생성 시점 실제 수, 이날 9,117→9,374 로 수집 중 변동)가 벽 없이 흐른다. 1차 시안은 불투명도 하나·간격 0.039px 라 **회색 금속판**으로 보였다(승우님 검수). 지금은 '재료' 하나로 그린다 — 선마다 불투명도 버킷 6개(y 를 따라 매끈한 띠 + 3% 진한 올), 결 둘(위상이 y 를 따라 돌아 다발이 모였다 벌어지는 것 + 선마다 무작위 위상으로 올이 넘나드는 것), 헤어라인 .3px. 실측 덮임(getImageData 평균) 33% — 종이에 회색 결, 틈에 종이가 보인다. 흐름은 결 있는 띠를 한 번 그려 CSS `translateX` 로만 민다(JS 0/프레임). 입력은 판이 아니라 **흐르는 종이 위의 괘선 한 줄** — 상자·그림자 없음, 글자 뒤에만 종이색 85% 스크림(box-shadow 로 번진 가장자리). 선은 글자 뒤로 지나간다.
- 상태 1: 목록은 entry-line 과 같은 콤보박스(`gen_entry.JS` 그대로). 목록이 스크롤돼도 키워드 행은 `sticky` 로 늘 보인다.
- 상태 2: 고르면 회사명이 입력 자리에서 머리 줄로 날고(FLIP), 물이 멎는다 — 띠의 현재 `transform` 위상을 읽어 캔버스가 **같은 그림**을 이어받는다(크로스페이드, 선은 다시 시작하지 않는다). 벽은 **`stageDone(k)` 호출마다** 위에서 300ms 에 **떨어지고**, 땅에 닿은 뒤 그 왼쪽 구간이 350ms 크로스페이드로 자유→체(벽 앞 눌림·통로로 수렴)로 재편된다. 전진선으로 쓸어 드러내지 않는다(1차 시안은 진행 막대처럼 읽혔다). 체 안의 막힌 선·자유 구간·도착 덩어리가 전부 같은 재료 함수라 이음새가 없다(엔진의 `mat` 훅: 버킷·펜·결). 체의 결은 멈춘 띠의 위상과 맞아야 하므로 엔진을 열쇠가 도는 순간에 만든다 — 기하+래스터 38ms. 시안은 타이머로 흉내(처음 0.7/1.5/2.3초, 재방문 칩 0.12/0.4/0.7초 + 속도 ×2), `?manual` 이면 밖에서 `stageDone(k)` 를 준다.
- 상태 3: flow.html 의 settled 와 같다(접힘·걸러낸 경로·표). 건너뛰기는 스테이지 클릭·Esc(판 안 클릭은 제외). 움직임 줄이기·캔버스 없음(`?nocanvas`)이면 Enter 가 바로 표.
- 키워드 길: 벽 둘(후보 풀 100 = 프런트 candidate_pool 기본값 → 12). 실제 키워드 결과 표본이 없어 표는 안 싣는다.
- 엔진 공유: `gen_flow.py` 의 JS 를 `ENGINE_JS`(Engine(C, cv, L, T, mat), 벽 수는 XS 길이, mat 없으면 flow.html 그대로) + `RUN_JS`(flow 전용 타임라인)로 쪼갰다. 내보내는 것: setup/draw/paint/labels/wall/Y/alive. flow.html 의 원천 JSON 은 임시 파일이라 없으므로 `gen_flow.py --rejs flow.html` 이 스크립트만 갈아끼운다. 831·385·12 와 표는 flow.html 에서 떼 온다(10-15 표본, 모수 9,285 — 오늘 수와 하루 어긋남).
- 프레임 비용(1×1 getImageData 강제 flush, 기준선 제외): 크로스페이드 중 4 blit 3.0~3.4ms, 벽 떨어지는 중 3.3ms, flow.html 3.4ms (1280px, dpr 1). 상태 0 은 JS 0/프레임.
- 약한 곳: 어떤 회사를 골라도 체·표는 한종산업개발 표본 하나(머리 줄만 고른 회사). 정지 화면의 결이 '강물'보다는 '빗어 넘긴 머리칼/직물'에 가깝다 — 다발이 사선으로 규칙적이라서(결 1 의 위상이 y 를 따라 2회전 + 요동). 간격 0.039px 에서는 올 하나가 보일 수 없고, 틈(접힘)에서만 종이가 보인다. 헤드리스 rAF 가 2fps 라 실시간 경로는 손으로 단계를 밟아 검증했다. 390px 에서 nav 두 줄(SHEET_CSS 공통).
