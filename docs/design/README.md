# 디자인 리뉴얼 — 2026-10-13 결정 사항

Phase 3(로드맵 `docs/roadmap-2026-10.md`) 작업의 기준점. 프로토타입은 `prototypes/`의 HTML을 브라우저로 열면 그대로 보인다(외부 의존 없음, Pretendard는 CDN).
생성 스크립트는 `scripts/`에 있고 `backend/.env`의 `DATABASE_URL`로 실제 공고·회사 데이터를 읽어 다시 만들 수 있다
(`python scripts/gen_main_toc.py out.html`, UMAP 지도는 umap-learn·scikit-learn 필요).

## 방향
- **제품 화면이 곧 랜딩.** 그래픽 비유(바코드·별자리·궤도 등)는 전부 검토 후 폐기. 실제 결과 표·실제 공고명·실제 숫자로만 만든다.
- 연출은 **Attio 문법**: 소프트 워시 배경 + 점 격자, 둥근 흰 카드(14~16px), 가는 회색 연결선, 파스텔 아이콘 타일·칩, 알약형 내비.
- 색: 먹 4단계 + 인주 `#e8431b` 하나. 마감 칩만 파스텔(D-1 인주, 7일 내 노랑). 다크 모드 없음.
- 서체 Pretendard, 표 숫자 tabular, 글자 크기 4단계(11 / 12.5 / 13.5 / 제목).

## 메인 페이지 구조 (`prototypes/main.html`)
1. **히어로** — 아이브로우 칩(오늘 N건), 큰 제목, 검색창. 그 아래 제품 화면. → 실제 결과·메일·공고 페이지가 완성되면 `prototypes/hero-scene.html`의 장면(가운데 실제 웹 + 위성 창: 아침 7시 메일 / 오늘 05:00 실행 / 공고 상세)으로 교체. 마우스 패럴랙스 없음.
2. **플랫폼 섹션** — 태그 + 두 톤 제목, **왼쪽 고정 목차**(읽기·어떻게·근거·골든타임·알림) + 오른쪽 블록. 스크롤 스파이, 진행 바.
   - 읽기: 결과 창(5건 공개 + 흐림 + 이메일 게이트)
   - 어떻게: 미니멀 워크플로우 캔버스(`prototypes/pipeline-canvas.html`) — 가중치·점수는 코드 값 그대로
   - 근거: "추천 근거" 카드(근거 4줄 + 점수 기여)
   - 골든타임: 라이프사이클 6단계 바
   - 알림: 실제 메일 모양
3. **CTA** — "처음 5건은 누구나, 전부는 이메일 하나로." + 이메일 한 칸
4. 푸터

## 모션 (CSS 트랜지션 + IntersectionObserver, 라이브러리 없음)
- 로드: 제목 줄 상승, 순차 페이드, 숫자 카운트업, 제품 창 rotateX → 펴짐
- 스크롤: 블록 리빌(60px 상승 + 94%→100%), 제목 밑줄, 패럴랙스(워시·창), 목차 진행 바, 단어 단위 제목 등장
- 블록별: 타이핑 → 행 스태거 → 흐림 → 게이트 / 선 그리기 + 노드 점등 / 행 슬라이드인 / 단계 점등
- 히어로 데모 루프: 가짜 커서가 회사명 타이핑 → 읽기 → 행 → 1행 클릭 "추천 근거" → 검토 인장 → 반복 (실제 DOM, 영상 아님)

## 제품 규칙 (디자인에 반영됨)
- 비로그인: 결과 상위 5건은 근거까지 전부 공개, 6건째부터 흐림 + "나머지 N건은 이메일로" 카드. 회사 SEO 페이지도 같은 규칙.
- 로그인 = 이메일 매직링크 = 알림 구독. 비밀번호 없음. 회사 기억·검토 인장 보관·아침 7시 새로 남은 공고 메일.
- 재방문은 비로그인이라도 브라우저가 회사를 기억해 "오늘 N건 중 볼 것은 M건" 상태로 연다.
- 공고 지도(UMAP, `prototypes/notice-map.html`)는 메인이 아니라 **별도 탐색 페이지**.
